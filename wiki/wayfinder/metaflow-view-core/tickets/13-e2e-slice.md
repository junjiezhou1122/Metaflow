## Question

Does the complete Browser/Screenpipe-to-evolving-View slice satisfy the confirmed product contract under real execution, feedback, failure, policy, and shared-surface conditions?

## Depends on

- Implement Feedback Views and explicit Transformation evolution
- Implement Failure Views and repair Transformations
- Project View Core through shared CLI, HTTP, and MCP operations

## Acceptance criteria

- Browser and Screenpipe evidence enters as immutable, idempotent Raw Views.
- A natural-language request resolves exact inputs and executes both a function and Agent Operator path.
- Output commits as a validated Derived View with complete trace.
- Feedback produces an improved Transformation and View revision.
- A forced failure produces a Failure View and a traceable repair result.
- Approve All with an explicit deny proves the denied View is not disclosed.
- CLI, HTTP, and MCP observe the same final graph.

## Verification method

- Run one automated end-to-end scenario with deterministic fixtures and fake Agent.
- Run live Browser and Screenpipe smoke checks separately where available.
- Record commands, expected outputs, traces, and known environmental limitations in the issue resolution.
